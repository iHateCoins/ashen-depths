# M07 PR03 — Warden-Gated Permanent Passive Points

## The agreed game rule
**One permanent passive point** becomes eligible when the current character defeats the **Warden on a previously uncompleted even depth**: 2, 4, 6, 8… Defeating each depth's Warden remains mandatory to descend, but only even-depth first victories produce passive points. **Successfully extracting banks those points**; merely entering a floor, opening a Cache or defeating the Warden does not write the save.

Example: defeat Wardens 1 and 2 → 1 point at risk; defeat Wardens 3 and 4 → 2 points at risk; extract at Depth 4 → bank both atomically with equipment, skill unlocks and Forge Embers. If the expedition ends in death or a browser restart before extraction, the point(s) at risk are lost. Repeat victories yield normal loot but never duplicate points.

## Class-specific progression
- **Vanguard** and **Arcanist** maintain *separate* first-clear ledgers, using their existing class IDs. Depth 2 defeated and secured as Vanguard is still available for Arcanist the first time.
- The current class carries its pending rewards between floors; class switching is blocked mid-expedition by the existing camp restrictions.
- The `passiveMilestones` record is optional in the current `ashen-depths-stash-v1` schema-1 save, e.g. `{ "vanguard":[2,4], "arcanist":[2] }`. Old saved characters default to zero banked points without migrations or deletion.
- Validation rejects odd, duplicate, unsorted, unreachable or out-of-range depths and unexpected class IDs. Bad saves are preserved for recovery, not overwritten.
- A selected class's saved milestones are loaded at the start of the expedition. A pending point cannot be banked for a different class, and already-secured depths cannot be banked a second time.

## Transaction and economy
- The existing `SecuredStash.secureExpedition(...)` transaction accepts an optional class/milestone payload as a **fourth argument**. Gear, unlocked skills, Forge Embers and passive milestones use one optimistic-locking localStorage write. A storage error or concurrent-tab update leaves the complete save unchanged and the expedition playable for retry.
- Existing one-use Forge Ember odds, drop probabilities, classes, skills and bag capacities are unchanged.
- Earned points are **not spent** by PR03. They are banked balances for M07 PR04 passive allocation/tree systems.
- The provisional depth cap remains 497; the deepest available passive milestone is Depth 496.

## Presentation
- Killing an eligible Warden shows `+1 PASSIVE POINT · UNSECURED`.
- The in-game objective/HUD shows `Passives N secured · M AT RISK`.
- The class toggle and its existing touch-friendly details panel show the point balances and explain the extraction requirement. No extra overlay blocks the dungeon.
- A successful extraction result reports the number of passive points secured for the current class.

## Automated acceptance
- Unit tests: 2/4/6 Warden gates, first-clear/repeated Warden handling, independent class ledgers, extraction-only banking, one-write saves with gear and Embers, rejected corrupt/duplicate entries, stale/failed storage writes, old stash compatibility.
- Playwright desktop, landscape touch, iPhone Safari:
  1. Depth 1 gives no point; descending to Depth 2 gives no point until its Warden falls; extraction secures exactly 1 point.
  2. Class switching shows separate previously banked milestones; repeating a Depth 2 victory does not give another point.
  3. Failed save does not bank the point; restarting discards only unsecured points without erasing existing records.

## Subsequent M07 development
**PR04:** Two compact branching passive trees (12–16 nodes per class initially), spendable points, meaningful offense/defense/hybrid choices, and saved passive allocations built atop these secured ledgers. Preserve gear as the dominant power source. Respect earned point balance and do not silently grant free respecs.

No automatic merge; owner approval and passing CI in all browser environments required.
