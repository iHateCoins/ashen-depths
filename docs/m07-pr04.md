# M07 PR04 — First branching passive trees

## Intent
Convert M07 PR03's extraction-secured first-clear Warden milestones into meaningful but **secondary** build specialization. Item power, equipment affixes and automated skill synergies remain the main progression motivators.

## Character-specific trees
- **Vanguard:** 12 passive nodes in Assault (physical Attack and tempo), Ward (health and armor), and Hybrid (Attack/Spell crossover) branches.
- **Arcanist:** 12 passive nodes in Assault (Spell Power and casting cadence), Ward (health and armor), and Hybrid (Spell/Attack crossover) branches.
- Each path is four sequential nodes; the previous node is required for the next. Players may spread points between paths freely, subject to prerequisites.
- Each node costs **exactly one banked passive point**. Defeating a Warden alone never makes its newly earned point spendable; that point must be secured through extraction.
- Current effects are flat Attack, Spell Power, Armor, Health and modest percentage reduction of automatic skill cooldowns. Totals are deliberately moderate relative to gear. Skill cooldown reduction applies *after* support multipliers and is hard-capped at 30%.
- Both classes can invest in their Hybrid branch, use off-class skills unlocked via discoveries, and wear any item base.
- The first version has **no respec**. Purchase UI labels permanent investments.

## Save integrity and compatibility
- Extend the existing **schema-1** stash with optional `passiveAllocations: { vanguard?: string[], arcanist?: string[] }`. Previous saved games (even with PR03's banked points) are valid and begin with zero allocations.
- Each saved allocation array records acquisition order, which is validated to ensure every prerequisite was previously bought. Invalid node IDs, duplicates, cross-class nodes, purchases exceeding *banked* milestone count, and malformed class keys invalidate saves safely, without overwriting existing bytes.
- Buying a node uses a revision-checked **single atomic write**, preserving the entire stash including earned passive milestones, weapons, skills, and Forge Embers. Failed quota/permissions/stale tab checks do **not** spend a point or apply an effect. A visible failure message asks players to retry.
- Extraction, forging and withdrawal retain allocations. No new save key, no migration, no cleanup of existing progress.
- Each class tracks its own passive allocations and banked points. Switching at the original entrance camp restores the chosen class's purchases without cross-class bonuses.

## Interaction and combat
- The existing CLASS modal now includes a mobile-scrollable **PASSIVE TREE** section with native buttons, three labeled paths, current effects, available points, prerequisite/owned/locked statuses and a point-spend confirmation by direct user tap. No new fixed UI panel overlaps movement controls.
- Players can inspect allocated nodes at any depth. **Purchases are permitted at the first entrance camp only**, not during combat or on deeper floors.
- Live bonuses affect the real basic attack, Attack-tagged skills, Spell-tagged skills, mitigation, maximum HP and cooldown calculations.
- Character health preserves missing-health semantics when maximum HP changes. Previously saved gear's own stats are unchanged.

## Acceptance gates
1. Existing pre-M07 saves load, and all previously earned banked points are available to the matching class.
2. Four earned Vanguard points can be allocated across branches; purchasing a locked 3rd-tier node before its prerequisites is impossible.
3. Allocating Iron Grip increases the real basic/Attack damage bonus; Stalwart increases max HP; Reinforced Mail reduces enemy contact damage; Measured Strikes reduces active-skill cooldown.
4. Class switch at camp loads its own tree. Cross-class allocations are never borrowed.
5. Browser reload preserves all bought nodes. Extraction and Forge Embers remain intact.
6. Blocked localStorage write leaves both permanent point balance and current combat stats unchanged. Lost connection/stale tab is not mistaken for a purchase.
7. Combat remains fluid and UI scrolls/taps accurately on desktop, landscape Chromium and iPhone Safari.

Automated coverage in `tests/passive-trees.test.ts`, `e2e/passive-trees.pw.ts` and all existing CI jobs.
