# M07 PR02 — Vanguard and Arcanist

## Purpose
Introduce two selectable starting archetypes while keeping equipment and skill build freedom. Class selection provides an early identity before the passive-point economy arrives. **Character progression remains the primary motivation; extraction secures rewards.**

## Classes
| Class | Starting HP | Basic attack | Starting automatic skill | Identity |
| --- | ---: | --- | --- | --- |
| Vanguard | 120 | 165px reach, 30 damage, 0.8s cadence | Crescent Cleave (Attack) | Short-range, sturdy attack-focused |
| Arcanist | 100 | 250px reach, 25 damage, 0.7s cadence | Cinder Burst (Spell) | Ranged caster, positioning |

Stats above are unmodified by equipment. Both classes use the **same slots**, Attack/Spell-affix system and two active skill sockets. Both can discover and equip cross-archetype skills. Selecting a class **does not lock weapons/armor/charms by type**.

## Character selection and safety
- Existing schema-1 saved characters remain **Arcanist by default**, with exactly the old combat and starting skill. No forced modal breaks existing saves, games or browser automated tests.
- A visible **CLASS: ARCANIST/VANGUARD** button opens a native touch-safe chooser with description and starting stats, available to inspect anywhere.
- A class can only be changed **on depth 1 at the original entrance camp before leaving it, looting or withdrawing any gear**. Choosing a class resets the starter skill and base attack configuration, but never destroys earned unlocks or secured items. A class change during a deeper floor or after combat is blocked.
- Class preference is stored as an optional `preferredClass` field in the **existing schema-1 stash**. Class selection is a deliberate preference that saves immediately, not a reward needing extraction. The stash key never changes, and optional absence means original Arcanist. Store writes use optimistic comparison; stale tabs, unavailable storage or full storage cannot report success or change the active class.
- Same secured stash, unlocked skill IDs and Forge Embers apply to either class for now. M07 PR03 will add class-specific passive-progression bookkeeping with unambiguous milestone ownership.

## Multi-floor integration
- A successful Warden gate and **DESCEND** carries the selected class, equipped auto skills/supports and active HP with its unsecured gear. A later-floor entrance does **not** reopen class selection.
- Extraction and death restart from depth 1 with the remembered class. Class preference does not grant skills or Embers by itself; cross-class skills must still be discovered and secured through extraction.
- Starting with Arcanist remains exactly backward-compatible: Cinder Burst unlocked, Crescent Cleave discoverable. Vanguard starts with Crescent Cleave and can discover Cinder Burst. Other unlocks retain their previous IDs.

## Verification
- Unit: class definitions and actual range/damage/health differences; proper starting ability and cross-class learning; old saves unaffected; atomic class preference writes and stale tab rejection; corrupt preference preserves original save bytes.
- E2E on desktop Chromium, landscape Chromium and iPhone WebKit: choose Vanguard, verify combat/HP/ability stats, kill Warden, descend, verify class and HP carried, block changing class at deeper floors, extract, return to depth 1 still Vanguard. Failure injection confirms no class or gear losses when localStorage writes fail.
- All existing stash, hybrid affix, forge, extraction and mobile UI regressions remain mandatory.
