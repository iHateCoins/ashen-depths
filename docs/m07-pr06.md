# M07 PR06 — Integration and technical-completion gate

## Scope
The user plans **one comprehensive M07 playtest after all M07 development is complete**, rather than incremental hands-on testing. This PR provides the automated gates and documented acceptance route before that session. It is **not an assertion that the user has tested or approved the gameplay**.

### Stability and depth scaling
- The old enemy HP scale stopped increasing at Depth 16 (`1 + min(depth - 1,15) * .18`), and the strike bonus stopped at +30, although equipment item levels kept rising by +2 per depth. This made deep floors progressively easier instead of creating a sustainable progression treadmill.
- `DepthBalance` preserves **identical behavior for floors 1–16**, then continues HP growth at +18% of baseline per floor and adds **+1 raw strike damage per floor after 16**. Armor mitigation remains effective; an appropriately leveled piece is no longer able to negate essentially all monster damage forever.
- Dungeon seeds, encounter populations, Warden variants, passive milestones, unique equipment bases, loot rarity, affixes, item levels and stash schema are **not altered** by this tuning.
- The provisional current maximum depth remains **497**, aligning item-level validator bounds (highest Warden item level 1000). This is an engineering cap, not a promised final endgame depth.
- The screen's debug data includes a named threat tier and strike bonus so browser tests and reports can identify the active scaling rules.

### Automated M07 integration gate
- TypeScript + all Vitest suites + production Pages build.
- Deterministic six-seed, eight-depth encounter sweep (depths 1, 2, 3, 4, 6, 8, 12, 24): exactly one Warden per floor, no elites promoted to Warden, all enemies occupy navigable cells, and spawn plans repeat exactly from the same floor seed.
- Depth balance samples 1, 2, 8, 16, 17, 32, 64, 128, 256 and 497: first sixteen levels unchanged, HP and strikes remain monotonically increasing beyond 16, highest equipment rolls validate at item level 1000, and leveled Armor mitigates without entirely nullifying hits.
- **Four-floor browser expedition:** fight Wardens at 1/2/3/4, carry equipped item stats and 17 missing health across floors, retain an unclaimed discovery until chosen, earn exactly two at-risk milestone points (Depths 2 and 4), then extract, atomically saving gear, 2 selected Forge Embers and both first-clear milestones. New expedition resets risky state and UI controls.
- **Separate class ledger browser expedition:** a Vanguard with an existing Depth 2 milestone and one bought Ward node receives no duplicate point at Depth 2, secures only Depth 4, and retains the Arcanist milestone ledger, purchased passive, old stash equipment, learned skill and currency.
- **Death browser expedition:** death after earning an unsecured even-depth point loses that point but preserves all previously banked class milestones and Forge Embers.
- Every browser expedition runs in isolated desktop Chromium, mobile landscape Chromium and iPhone Safari WebKit CI. The longer four-floor scenario is intentionally allowed up to 90 seconds per test (normal per-test timeout remains 45 seconds).

## Required human acceptance (after PR06 merged)
GitHub Actions cannot determine whether combat *feels* good, whether a browser frame stutters under real input, whether enemies are visually distinct enough on a phone, or whether the risk/reward decision is enjoyable. These remain **unverified until the user's complete M07 playtest**. The test plan is in `docs/m07-playtest.md`.

## M07 completion conditions
1. All four jobs (build, desktop, mobile landscape, iPhone Safari) pass at the PR06 HEAD.
2. The project owner reviews and merges PR06; no auto-merge.
3. Run the consolidated human M07 checklist; triage/fix blocker and major defects in M07 maintenance PRs before starting M08.
4. Upon an accepted playtest, mark M07 complete and begin M08 visual/audio/UX polish.
